# Как выложить проект на Vercel и собрать фидбэк

> Инструкция для этого проекта: React SPA (`frontend/`) + NestJS API (`src/`) + PostgreSQL.
> Все шаги проверены на реальной сборке; там, где нужны действия только в браузере
> или в вашем аккаунте, это помечено отдельно.

## Сначала — важное ограничение Vercel

Vercel умеет хостить **только статику и serverless-функции**. В нашем проекте:

| Часть | Можно на Vercel? | Почему |
|---|---|---|
| `frontend/` (React SPA) | **Да** | Это статика, идеальный случай для Vercel |
| `src/` (NestJS API) | **Нет** | Нужен постоянно живущий Node-процесс с подключением к БД и подключённым `sharp` |
| PostgreSQL | **Нет** | Нужна БД с постоянным диске; у Vercel его нет |

Поэтому используется схема **«фронтенд на Vercel + API и БД отдельно»**.
Для тестирования друзьями в проекте есть `docker-compose.yml`, который нужно
где-то развернуть.

Ещё один нюанс: у API есть **загружаемые файлы** (фото продуктов, фото фигуры
в `uploads/`, том Docker). На Vercel файловая система только для чтения, так
что API там работать не может в принципе.

## Шаг 1. Выложить API и базу

Нужен любой хост с Docker или с Node + PostgreSQL. Варианты:

- **Домашний компьютер** — самый быстрый вариант для «друзья потестируют»:
  поднять проект локально и отдать наружу через туннель.
- **VPS** (любой провайдер) — стабильнее, если тест длится недели.

### Вариант А. Локально + туннель (быстро)

```bash
# 1. Собираем и запускаем проект как обычно
./rebuild.sh api
./rebuild.sh web

# 2. Отдаём наружу HTTPS-адрес API (туннель сам выдаст публичную ссылку)
npx localtunnel --port 3000
# или: cloudflared tunnel --url http://localhost:3000
```

Из вывода команды скопируйте публичный адрес — он понадобится в Шаге 3.
Учтите: пока компьютер выключен или туннель закрыт, сайт на Vercel
не сможет получить данные.

### Вариант Б. VPS через Docker Compose

```bash
git clone <ваш-репозиторий> && cd course
# заполните .env (см. .env.example): БД, JWT, OPENROUTER_API_KEY, Stripe
docker compose up -d
```

Понадобится домен и HTTPS. Без HTTPS браузер заблокирует запросы
с Vercel (смешанный контент), поэтому сертификат обязателен —
подойдёт бесплатный Let's Encrypt.

## Шаг 2. Разрешить запросы с домена Vercel (CORS)

Бэкенд принимает только перечисленные источники. Пока домена Vercel в списке
нет, запросы будут падать с ошибкой CORS — **это самая частая причина
«на Vercel ничего не работает»**.

В `docker-compose.yml` (или в `.env`, откуда подставляется значение):

```yaml
CORS_ORIGINS: https://localhost,https://ВАШ-ПРОЕКТ.vercel.app,https://ВАШ-ДОМЕН.vercel.app
```

Домены предпросмотра у Vercel каждый раз новые (`*-git-ветка-*.vercel.app`).
Чтобы не пересобирать API после каждой ветки, добавьте их списком или
укажите конкретный основной домен и тестируйте на нём.

После правки — перезапуск API.

## Шаг 3. Задеплоить фронтенд на Vercel

### Через сайт Vercel (проще)

1. Залейте проект на GitHub (нужен весь репозиторий, не только `frontend/`).
2. На [vercel.com](https://vercel.com) → **Add New → Project** → выберите репозиторий.
3. В настройках проекта:
   - **Root Directory**: оставьте пустым (корень репозитория).
   - **Framework Preset**: `Vite` (подхватится из `vercel.json`).
   - **Build Command / Output Directory**: уже заданы в `vercel.json`,
     менять не нужно.
4. Раскройте **Environment Variables** и добавьте:

   | Имя | Значение | Обязательно |
   |---|---|---|
   | `VITE_API_BASE_URL` | `https://адрес-вашего-API/api` | да |
   | `VITE_SUBSCRIPTION_PRICE` | `9.90 $` | нет |

   Префикс `/api` в конце обязателен — без него фронтенд обратится
   по неверному пути и получит 404.
5. **Deploy**. Через минуту получите адрес вида `https://проект.vercel.app`.

### Через CLI (если предпочитаете терминал)

```bash
npm i -g vercel
cd /путь/к/проекту
vercel                 # первый деплой, отвечает на вопросы
vercel --prod          # боевой деплой
```

Переменные задаются так:

```bash
vercel env add VITE_API_BASE_URL production
# вставьте https://адрес-вашего-API/api
vercel --prod          # пересобрать с новой переменной
```

> **Важно:** `VITE_*` переменные «впечатываются» в бандл **во время сборки**.
> Если поменяли значение — нужно задеплоить заново, одного «сохранения»
> переменной недостаточно. Это проверено: после сборки адрес лежит
> прямо в JS-файле.

## Шаг 4. Проверить, что всё работает

Пройдите по пунктам — каждый ловит свою типичную ошибку:

1. **Страница открывается.** Перейдите по адресу Vercel — должен
   отрисоваться экран входа. Пустой белый экран = ошибка сборки,
   смотрите **Deployments → Build Logs**.
2. **Прямые ссылки работают.** Откройте `https://проект.vercel.app/profile`
   и обновите страницу (F5). Не должно быть 404 — за это отвечает
   блок `rewrites` в `vercel.json`.
3. **API отвечает.** В консоли браузера на странице проекта:
   ```js
   fetch('https://адрес-вашего-API/api/health').then(r => r.json())
   ```
   Ожидается `{ "status": "ok" }` или похожий ответ.
   - Ошибка CORS → вернитесь к Шагу 2.
   - `Failed to fetch` → API недоступен или нет HTTPS.
4. **Вход работает.** Зарегистрируйтесь или войдите тестовым аккаунтом.
   Ошибка 404 на `/auth/login` означает, что в `VITE_API_BASE_URL`
   забыт префикс `/api`.
5. **Картинки на месте.** На главной должен быть виден фон с паттерном
   из еды, на странице анализа тела — силуэт человека.

## Шаг 5. Собрать фидбэк по UX/UI

Чтобы отзывы были предметными, а не «нормально/не очень», дайте друзьям
конкретные задания:

- **Первый запуск.** Попросите заполнить профиль и сгенерировать план
  питания на 7 дней, ничего не объясняя. Где человек застрял — там
  проблема интерфейса.
- **Три вопроса после каждого экрана:** что вы хотели сделать? что
  сделали? что вас запутало?
- **Тёмная тема.** Попросите переключить тему и пройти те же шаги —
  контраст и читаемость в тёмной теме часто ломаются отдельно.
- **Телефон.** Попросите открыть с телефона: меню, таблицы плана питания
  и холодильник — самые проблемные места на узком экране.

Что важно предупредить тестировщиков заранее:

- Подписка оплачивается **тестовой картой** (`4242 4242 4242 4242`,
  любой будущий срок, любой CVC). Реальные деньги не списываются.
- **Регистрация по email может не работать** — почтовый сервер не
  настроен. Используйте готовые тестовые аккаунты:
  `user1@example.com / Testpass123`, `admin@example.com / Adminpass123`.
- ИИ-функции (чат, распознавание еды, генерация плана) обращаются
  к внешнему сервису и могут отвечать медленно — до 10–20 секунд.
  Это нормально, у кнопок есть индикатор загрузки.

Куда собирать отзывы:

- **Google Forms / Яндекс Формы** — если тестировщиков много.
- **GitHub Issues** — если хотите привязать отзыв к конкретному экрану
  (попросите приложить скриншот и путь страницы).
- **Один общий чат** — быстрее всего, но отзывы будет сложно
  систематизировать.

## Частые ошибки и что они значат

| Симптом | Причина | Решение |
|---|---|---|
| `CORS policy: No 'Access-Control-Allow-Origin'` | домен Vercel не в `CORS_ORIGINS` | добавьте домен, перезапустите API (Шаг 2) |
| Белый пустой экран | ошибка сборки или падение JS | смотрите Build Logs и консоль браузера |
| 404 при обновлении страницы | не работает SPA-роутинг | проверьте блок `rewrites` в `vercel.json` |
| 404 на `/auth/login` | в `VITE_API_BASE_URL` нет `/api` | исправьте переменную и передеплойте |
| `Failed to fetch` | API недоступен или нет HTTPS | откройте адрес API в браузере напрямую |
| Старый адрес API после смены переменной | `VITE_*` вшиваются при сборке | запустите деплой заново |
| Картинок нет, фон пустой | не задеплоились файлы из `public/` | проверьте, что сборка даёт `food-pattern.svg` в корне `dist/` |

---

## Что уже подготовлено в проекте

- **`vercel.json`** — команда сборки, папка вывода, SPA-роутинг
  и кэширование статики. Менять ничего не нужно.
- **`frontend/.env.example`** — пример переменных окружения
  с пояснениями.
- Сборка проверена отдельно от Docker: `cd frontend && npm run build`
  собирается без ошибок и кладёт в `dist/` все нужные файлы, включая
  фон `food-pattern.svg`.
