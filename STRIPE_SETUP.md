# Где взять данные для Stripe

В проекте используются четыре значения из личного кабинета Stripe.
Ниже — где именно каждое лежит и как проверить, что оно рабочее.

> **Сначала главное.** Ваш текущий ключ в `.env` — `rkcs_test_...`
> («claimable sandbox»), и он **истёк**. Stripe отвечает на него:
> `api_key_expired`. Из-за этого кнопка «Управлять подпиской» отдаёт
> ошибку 400, а оформить новую подписку нельзя. Такой ключ выдаётся
> на ограниченный срок; для постоянной работы нужен обычный тестовый
> ключ `sk_test_...` из своего аккаунта.

---

## Что нужно и где лежит

| Переменная в `.env` | Где взять в Stripe |
|---|---|
| `STRIPE_SECRET_KEY` | Developers → API keys → **Secret key** (`sk_test_...`) |
| `STRIPE_PUBLISHABLE_KEY` | Developers → API keys → **Publishable key** (`pk_test_...`) |
| `STRIPE_PRICE_ID_MONTHLY` | Products → ваш товар → цена → **Price ID** (`price_...`) |
| `STRIPE_WEBHOOK_SECRET` | Developers → Webhooks → ваш endpoint → **Signing secret** (`whsec_...`) |

### 1. Ключи API

1. Откройте [dashboard.stripe.com](https://dashboard.stripe.com) и войдите.
2. Убедитесь, что **переключатель «Test mode» включён** — иначе увидите
   боевые ключи `sk_live_`, а проект их намеренно не принимает
   (`isLiveKey` в `src/config/stripe.ts` вернёт ошибку).
3. Слева: **Developers → API keys**.
4. Скопируйте **Publishable key** (`pk_test_...`) — он публичный.
5. Нажмите **Reveal test key** у **Secret key** и скопируйте `sk_test_...`.
   Секретный ключ показывается один раз — сохраните его сразу.

В `.env`:

```
STRIPE_SECRET_KEY=sk_test_51...
STRIPE_PUBLISHABLE_KEY=pk_test_51...
```

### 2. Price ID подписки

1. **Products** (или Product catalog) → **Add product**.
2. Название, например «Подписка на ИИ-функции».
3. В блоке цены: **Recurring**, сумма `9.90`, валюта **USD**, период
   **Monthly**.
4. Сохраните и откройте товар: в разделе цен будет **API ID** вида
   `price_1UOLde...` — это и есть Price ID.

```
STRIPE_PRICE_ID_MONTHLY=price_1...
```

Сумма здесь должна совпадать с `SUBSCRIPTION_PRICE_USD` в
`src/subscription/subscription.service.ts` — именно по ней карточка
подписки считает цену в белорусских рублях.

### 3. Секрет вебхука

Вебхук сообщает приложению об оплате. Без него подписка активируется
только при возврате со страницы оплаты (резервный механизм `sync`,
он уже реализован).

**Если тестируете на своём компьютере** — удобнее через Stripe CLI:

```bash
# установка: brew install stripe/stripe-cli/stripe
stripe login
stripe listen --forward-to https://localhost/api/stripe/webhook
```

CLI выведет строку `whsec_...` — вставьте её в `.env`. Эта команда
должна быть запущена, пока вы тестируете оплату.

**Если API развёрнут на сервере:**

1. **Developers → Webhooks → Add endpoint**.
2. URL: `https://ваш-домен/api/stripe/webhook`.
3. События: `checkout.session.completed`,
   `customer.subscription.updated`, `customer.subscription.deleted`.
4. После создания откройте endpoint и скопируйте **Signing secret**.

```
STRIPE_WEBHOOK_SECRET=whsec_...
```

## Как проверить, что ключ рабочий

Самый быстрый способ — обратиться к Stripe напрямую из терминала.
Подставьте свой ключ:

```bash
curl -s -u "sk_test_ВАШ_КЛЮЧ:" https://api.stripe.com/v1/customers?limit=1
```

- Список клиентов в ответе → **ключ рабочий**.
- `"code": "api_key_expired"` → ключ истёк, нужен новый.
- `"code": "api_key_invalid"` → ключ скопирован с ошибкой.

Проверить сразу все настройки проекта можно так — API сам скажет,
что не так:

```bash
curl -s -k -X POST https://localhost/api/subscription/checkout \
  -H "Authorization: Bearer ВАШ_ТОКЕН"
```

- `{"url":"https://checkout.stripe.com/..."}` → всё настроено.
- «Платежи недоступны: не задан STRIPE_SECRET_KEY» → ключа нет в `.env`.
- «используется боевой ключ» → включён боевой режим, нужен тестовый.
- «не задан STRIPE_PRICE_ID_MONTHLY» → не указан Price ID.

## После изменения `.env`

Переменные читаются при старте процесса, поэтому нужен перезапуск:

```bash
./rebuild.sh api
```

Изменения в `.env` без перезапуска не подхватятся — это относится и к
секретному ключу, и к Price ID, и к секрету вебхука.

## Тестовая оплата

В тестовом режиме реальные деньги не списываются. Карта для проверки:

| Поле | Значение |
|---|---|
| Номер | `4242 4242 4242 4242` |
| Срок | любая будущая дата |
| CVC | любые 3 цифры |

После оплаты вернитесь в профиль: приложение само проверит подписку
через `sync` и покажет статус «Активна». Если вебхук не настроен —
это ожидаемо, сработает резервная проверка при возврате.

## Куда смотреть, если что-то не работает

| Что видно | Причина | Что делать |
|---|---|---|
| 400 и «Не удалось открыть управление подпиской» | ключ истёк или неверный | проверьте ключ командой `curl` выше |
| 400 и «Платежи недоступны» | не задан `STRIPE_SECRET_KEY` | заполните `.env`, перезапустите API |
| Подписка не активируется после оплаты | не пришёл вебхук | запустите `stripe listen` или проверьте endpoint; резервно — кнопка «Обновить статус» |
| «Не задан STRIPE_PRICE_ID_MONTHLY» | нет Price ID | создайте товар и цену (шаг 2) |
| Цена в BYN не совпадает с ожидаемой | сумма в Stripe ≠ `SUBSCRIPTION_PRICE_USD` | приведите их к одному значению |

> Ошибки Stripe теперь показываются пользователю нейтральным текстом,
> а причина с замаскированным ключом уходит в лог API — смотрите
> `docker compose logs api`.
