## 1. Что за проект

**AI-Nutrition-Plan-Course** — курсовой проект: клиент-серверное SPA для
персонального планирования питания.

**Репозиторий:** https://github.com/AndreyChiruk/AI-Nutrition-Plan-Course (ветка `master`)

**Что умеет:** генерация планов питания (AI + каталог блюд), учёт аллергий и
пищевых ограничений, «холодильник» (личные продукты с фото), распознавание
еды по фото, AI-чат, анализ тела по фото, статистика, планы тренировок,
подписка Stripe, админ-панель модерации.

### Стек (точные версии — не менять без необходимости)

| Слой | Технологии |
|---|---|
| Backend | NestJS 11.0.1, TypeScript, Node.js 22 (`.nvmrc` = 22) |
| ORM/БД | Sequelize 6.37.8 + sequelize-typescript 2.1.6, PostgreSQL 16 |
| AI | `openai` 6.34.0 как клиент, фактический провайдер — OpenRouter |
| Прочее | Stripe 23.0.0, multer 2.4.0, sharp 0.34.5, nodemailer 8.0.5, winston 3.19.0, `@nestjs/throttler` 6.5.0, `@nestjs/cache-manager` 3.1.0 |
| Frontend | React 19.2.4, react-router-dom 7.14.1, Vite, axios 1.15.0, recharts 3.8.1, lucide-react 1.8.0 |
| Инфра | Docker Compose: `postgres`, `api`, `web` (nginx 1.27-alpine) |

### Масштаб

- Backend: ~22 400 строк TS (без тестов), 24 каталога модулей.
- Frontend: ~12 300 строк, 14 страниц.
- Модели: 29 (`src/models/`). Миграции: 33 (`database/migrations/*.sql`).
- Тесты: 74 unit (`src/tests/unit/`) + 1 интеграционный.
- Сырых `sequelize.query(...)`: 40 — учитывай при правках SQL.

## 2. Как запускать и проверять

### Команды

```bash
npm run build        # nest build — должно проходить ВСЕГДА
npm test             # 74 unit-теста (mocha)
npm run test:integration
npm run start:dev    # локальный запуск с watch
```

### Полный стек в Docker

```bash
./rebuild.sh          # пересобирает только web (по умолчанию)
./rebuild.sh api      # только backend
./rebuild.sh all      # оба
```

Сервисы поднимаются на `https://localhost` (nginx, самоподписанный TLS)
и `http://localhost:3000` (api напрямую).

### Обязательные проверки после КАЖДОЙ задачи

1. `npm run build` — без ошибок.
2. `npm test` — не должно стать хуже, чем было.
3. Если задача меняла SQL/модели — подними БД и проверь миграции.
4. Если менялся фронтенд — `cd frontend && npm run build`.

**Правило:** не переходи к следующей задаче, пока текущая не собирается.

## 3. Правила работы (важно)

### 3.1. Сохраняй публичные интерфейсы

Проект рабочий. Любой рефакторинг (особенно задачи 21 и 22 — декомпозиция
больших файлов) **не должен менять**:

- имена классов, декораторов и экспортов;
- сигнатуры публичных методов сервисов;
- HTTP-маршруты и их поведение;
- публичные пропсы React-компонентов.

Меняется **внутренняя структура**, а не контракт.

### 3.2. Одна задача — один коммит

Коммить каждую задачу отдельно. Это позволит откатить любую правку:

```bash
git add -A
git commit -m "Задача N: <что сделано>"
```

При откате: `git revert <hash>` (не `reset --hard` — он уничтожает историю).

### 3.3. Не ломай то, что уже исправлено

Ниже — правки, сделанные ранее в этой сессии. **Не откатывай их и не
«улучшай»**, они проверены:

- **`docker-compose.yml`**: сервису `api` добавлен том `uploads:/app/uploads`.
  Без него загруженные фото продуктов удалялись при пересборке контейнера,
  хотя запись в БД оставалась (было 404 + заглушка).
- **`src/common/jwt.config.ts`**: централизует `JWT_SECRET`, запрещает
  небезопасные значения (`dev-secret`, `secret` и др.). Обход только через
  `ALLOW_INSECURE_JWT_SECRET=1` для локальной разработки.
- **`.dockerignore` + `frontend/.dockerignore`**: уменьшили контекст сборки
  с 595 МБ до 7 МБ. **Важно:** в корневом `.dockerignore` нельзя добавлять
  шаблон `*.sql` — он исключит `database/migrations/*.sql` (33 файла), и образ
  останется без миграций. Именно поэтому дампы перечислены по именам.
- **Dockerfile**: `RUN --mount=type=cache,target=/root/.npm` для кэша npm.
  Директиву `# syntax=docker/dockerfile:N` **добавлять не нужно** — она
  заставляла BuildKit тянуть образ из Docker Hub, и при недоступном registry
  сборка падала ещё до начала работы.
- **CSS-тема**: тёмная тема отключена намеренно (переключатель и логика
  убраны, `data-theme` зафиксирован на `light`). Правила для `html[data-theme='dark']`
  в CSS оставлены — не удаляй их.

### 3.4. Известные ловушки проекта

- **`DB_AUTO_SYNC: '1'`** в `docker-compose.yml` включает
  `synchronize: true` (`src/app.module.ts:64`) **при наличии 33 миграций**.
  Это два конкурирующих источника истины для схемы — задача 1 как раз про это.
  Правь осторожно: изменение `synchronize` влияет на старт приложения.
- **ПОДТВЕРЖДЕНО ЧТЕНИЕМ КОДА** (эти три дефекта реальны, не гипотезы):
  - `src/auth/auth.bootstrap.service.ts` вызывает `ensureMealPlannerSchema`
    при каждом старте, а тот без условий прогоняет `013_fridge_mass_units.sql`
    (там `UPDATE fridge_items SET unit='г' WHERE unit NOT IN ('г','кг',…)`).
    То есть при каждом рестарте все `мл` и `шт` в холодильнике превращаются
    в `г` — необратимая порча данных пользователей.
  - `POST /meal-plan/generate-ai-catalog` и `POST /meal-plan/refine-constructor-ai`
    не имеют `RequireSubscriptionGuard` — любой авторизованный человек без
    подписки может бесконечно жечь баланс OpenRouter.
  - `ThrottlerModule.forRoot([{ ttl: 60_000, limit: 100 }])` подключён,
    но в провайдерах **нет `APP_GUARD`** — лимит фактически не действует.
- **`src/tests/unit/users.service.test.ts` не компилируется**: ошибка
  `TS2554: Expected 5 arguments, but got 3` в 7 местах — конструктор
  `UsersService` вызывается с 3 аргументами вместо 5 (`ingredientModel`,
  `fridgeImageStorage`). Файл `src/common/password.util.ts` **существует**
  и работает — искать проблему с ним не нужно (это была ошибка предыдущего аудита).
  `npm run build` при этом проходит, потому что `nest build` тесты не собирает.
  Это задача 18.
- **Иконки SVG через `<img>`**: `currentColor` внутри изолирован и не работает,
  рендерится чёрным. В проекте используется CSS-фильтр. Не «исправляй» на
  `fill="currentColor"`.
- **`PLAIN_ICONS = true`** в `frontend/src/components/icons.tsx` — намеренный
  режим. Пустые `.icon-placeholder` скрыты глобальным `display: none`.

### 3.5. Стиль кода

- Язык комментариев и сообщений коммитов — **русский**.
- Имена файлов, функций, типов, команд — **как в коде** (не переводить).
- Комментарии объясняют **почему**, а не «что» — следуй уже принятому в проекте стилю.
- Не добавляй зависимости без необходимости. Если задача требует новую
  библиотеку — сначала спроси, зачем, и предложи вариант без неё.

## 5. Чего НЕ делать

1. **Не переписывать проект с нуля** и не менять стек.
2. **Не добавлять новые фичи** — задача только в исправлении найденного.
3. **Не удалять тесты**, чтобы «прошло». Если тест падает из-за правки —
   разберись, кто прав.
4. **Не коммитить секреты**: `.env` в `.gitignore`, ключи AI/Stripe только
   через переменные окружения. Не вставляй реальные ключи в код и логи.
5. **Не менять `package-lock.json` вручную** и не обновлять версии зависимостей
   без явной необходимости — это может сломать сборку.
6. **Не трогать** `database/migrations/*.sql` (уже применённые миграции);
   для изменений схемы создавай **новую** миграцию со следующим номером.
7. **Не использовать `git push --force`** и `git reset --hard`.

## 7. Если чего-то не хватает

Отчёт Argon составлен по статическому чтению кода. Возможны случаи, когда:

- файл или строка уже изменились;
- предлагаемая правка конфликтует с другой задачей;
- для проверки нужен запущенный сервис или доступ к БД.

В этих случаях: **остановись и напиши**, что именно нужно уточнить.
Не догадывайся и не вноси изменения «наугад» — проект рабочий, и это
важнее скорости.
