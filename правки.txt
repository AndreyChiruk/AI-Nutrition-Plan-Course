## REG-1. Силуэт человека не отображается

Компонент <BodySilhouette /> (или как называется) не рендерится на
странице «Анализ тела».

Проверить:
- импорт компонента в страницу;
- наличие <svg> в DOM (DevTools);
- не 0×0 ли размер (width/height/viewBox);
- не перекрыт ли другим блоком (z-index/position);
- приходят ли props zones/gender — если undefined, компонент может
  возвращать null;
- ошибки в консоли браузера (если увидишь — напиши мне в отчёте,
  я скину);
- если использовалась react-body-highlighter — проверить установку
  (npm ls) и совместимость с React-версией.

Добавить fallback: если zones пусты — рендерить базовый контур
с нейтральным цветом, не пустоту.

## REG-2. Картинки блюд растянуты

Найти компонент карточки блюда. Для <img>: object-fit: cover,
aspect-ratio: 4/3 (или 16/9), width: 100%; height: auto.
Убрать жёсткие width/height в px. Добавить onError с плейсхолдером.

## REG-3. Дропдаун в холодильнике сливается с фоном

Найти компонент поиска в холодильнике (может быть свой, отдельный
от общего). Проверить базовый стиль без :hover — сейчас видно только
при наведении. Задать явный background, border, box-shadow, z-index.
Если используется общий компонент автокомплита — фикс в нём.

## REG-4. Главная страница — добавить контент

Блок «Как это работает» (3-4 шага), блок примеров блюд из БД (3-4 карточки),
блок метрик (кол-во блюд/пользователей). SVG-иллюстрации, не стоковые фото.
Hero компактнее + визуальный элемент. Не больше 3-4 блоков.

## REG-5. Аудит Nginx как HTTPS-прокси

Проверить docker-compose.yml и docker/nginx/:
- listen 443 ssl;
- сертификат в docker/nginx/certs/;
- редирект http→https (return 301);
- ssl_certificate / ssl_certificate_key;
- location /api → proxy_pass на api:3000;
- location / → proxy_pass на web:80 или статика;
- security headers: HSTS, X-Content-Type-Options, X-Frame-Options,
  Referrer-Policy;
- TLS ≥ 1.2.

Проверка: curl -kI https://localhost, curl -kI http://localhost
(должен быть 301), curl -k https://localhost/api/health.
Если чего-то нет — исправить конфиг.

## STRIPE-3. Модели и миграция

Новая миграция:
- subscriptions: id, user_id (FK, unique), stripe_customer_id,
  stripe_subscription_id, status ENUM('active','past_due','canceled',
  'incomplete','trialing','unpaid','none') default 'none',
  current_period_end DATE, cancel_at_period_end BOOL default false,
  created_at, updated_at.
- ai_chat_usage: id, user_id, date, messages_count INT default 0,
  UNIQUE(user_id, date).

Модели Sequelize: Subscription, AiChatUsage. User hasOne Subscription.

## STRIPE-4. Checkout и статус

POST /api/subscription/checkout (auth):
- найти/создать Stripe Customer (stripe.customers.create с email,
  metadata.user_id); сохранить customer_id.
- Checkout Session: mode subscription; line_items
  [{price: STRIPE_PRICE_ID_MONTHLY, quantity: 1}]; customer;
  success_url `${APP_URL}/profile?subscription=success`;
  cancel_url `${APP_URL}/profile?subscription=canceled`;
